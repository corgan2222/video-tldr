# Notes for coding agents

Orientation for an agent working in this repository. The rules for everyone
who contributes are in [CONTRIBUTING.md](CONTRIBUTING.md) and are not repeated
here. Read that file first. Its one rule, "Measured, not assumed", covers agent
work too.

## What this program is

A Manifest V3 browser extension for Firefox and Chrome.

Written in TypeScript, tsc, vitest, prettier.

## Code map

| Path           | What lives there                                    |

Add a row when a new area appears; a row per file is an index that `grep`
keeps better.

## Do not touch

- `node_modules/`. Installed by `npm ci`, never edited.
- `dist/`. Build output; regenerated by the build.
- `website/node_modules/`, `website/out/`. Installed and built, never edited.
- `LICENSE`, `CODE_OF_CONDUCT.md`. Standard texts, not project prose.

## Read before you change

Read a file before you edit it. Search for every caller before you change a
function.

## Where a new finding goes

Walk this ladder from the top. Stop at the first step that fits.

1. A regression test can catch it. Write the test.
2. A lint or CI rule can catch it. Add the rule, and word the error message so
   that it names the way out.
3. Only prose explains it. Put a comment at the code it applies to.

## Commands

[CONTRIBUTING.md](CONTRIBUTING.md) covers the setup, the git hooks and what
each check is for. This table is the short reference.

| Purpose       | Command                  |
| ------------- | ------------------------ |
| Format check  | `npx prettier --check .` |
| Lint          | `npm run lint`           |
| Test          | `npm test`               |
| Release build | `npm run build`          |

End every finished item with a release build: `npm run build` compiles
`src/*.ts` and copies everything else under `src/` (manifest, popup, icons)
into `dist/`, the directory the browser loads. `npx web-ext lint
--source-dir dist` then checks the result the way a store reviewer does.
A build that passed the tests but not the lint is not a shipped one.

Versions follow semantic versioning. The number lives in `package.json`,
and `scripts/bump_version.py` writes the same number into
`src/manifest.json`, the file the stores read; `tests/version.test.ts`
fails when the two drift. Until the first release tag exists, every commit
bumps the patch number: the pre-commit hook runs the bump script, which
stops on its own once a tag is there. From then on the number moves only
with a GitHub release: set it in `package.json`, run the bump script with
`--set`, publish the draft, and `.github/workflows/release.yml` refuses to
build when tag and `package.json` disagree. Before a release,
`git log --oneline v<version>..HEAD` must be empty. A tag that stays put
while the work goes on ships the old state.

## Testing from the command line

A browser extension has no process to pass a flag to, so the command line
reaches it through its modules: the logic of every feature lives in a plain
module that a vitest test imports and calls, and popup, background and
content scripts stay thin callers of those modules. Verification happens by
command: `npm test`, `npm run build`, `npx web-ext lint --source-dir dist`.
Clicking through the popup is for acceptance once those are green, not for
finding out whether something works in the first place.

## Browser extension conventions

One manifest serves both browsers. Firefox has read Manifest V3 since
version 109, so there is no separate Firefox build, only the
`browser_specific_settings.gecko` block the shared manifest already
carries.

- Call the `browser.*` namespace, not `chrome.*` directly. Load the
  `webextension-polyfill` shim, or check `typeof browser !== 'undefined'`
  before falling back to `chrome.*`. Code that only knows `chrome.*` breaks
  on Firefox.
- No remote script, no remotely hosted code, no `eval` of a fetched string.
  Every store rejects an update that loads code from outside the package;
  everything the extension runs ships inside `dist/`.
- Keep `permissions` at what `manifest.json` needs today. A broad host
  permission slows every store review and is usually the first thing a
  reviewer flags.
- `web-ext run --source-dir dist` loads the built extension into a real
  Firefox profile for a manual click-through. `web-ext lint` is what CI
  runs, and it is close to the check a Firefox reviewer runs before
  publishing an update.
